# AURORA VISION — Advanced AI Face Matching Laboratory

تطبيق Android حقيقي لمطابقة الوجوه يعمل **بالكامل على الجهاز** (بدون خادم، بدون مفاتيح API)،
بواجهة عربية من اليمين إلى اليسار مستوحاة من مختبرات التحليل البصري في أفلام الخيال العلمي.

> **تنبيه أساسي:** درجة التشابه مقياس بصري وليست دليلًا قاطعًا على الهوية.
> النظام مخصص للبحث داخل مجموعة صور **مصرح باستخدامها** فقط، ولا يجمع صورًا من الإنترنت
> ولا يحدد هويات مجهولة.

---

## 1. ما تم تنفيذه فعليًا

| القدرة | الحالة | الدليل |
|---|---|---|
| اكتشاف الوجوه (شبكة عصبية حقيقية) | ✅ يعمل | YuNet ONNX، اختبار تكافؤ مع مرجع Python |
| محاذاة الوجه بـ 5 نقاط (Umeyama) | ✅ يعمل | مقارنة رقمية مع تطبيق OpenCV المرجعي |
| استخراج تمثيل رقمي 128 بُعدًا | ✅ يعمل | SFace MobileFaceNet ONNX |
| فحص جودة الوجه | ✅ يعمل | عتبات مُعايرة على توزيعات مقاسة |
| قاعدة صور مسجلة (إضافة/حذف/إعادة فهرسة) | ✅ يعمل | Room + ملفات مشفّرة |
| بحث فعلي وترتيب النتائج | ✅ يعمل | بحث شامل + اختبار 20,000 سجل |
| حالة «لا يوجد تطابق موثوق» | ✅ يعمل | `MatchVerdict.NO_RELIABLE_MATCH` |
| سجل عمليات البحث + الحذف | ✅ يعمل | Room + حذف الصور المرتبطة |
| قياسات دقة موثقة (AUC/EER/FAR/FRR) | ✅ مقاسة | [`docs/EVALUATION.md`](docs/EVALUATION.md) |
| بناء APK عبر GitHub Actions | ✅ يعمل | `.github/workflows/android-ci.yml` |
| اختبارات وحدة للمنطق الأساسي | ✅ تعمل على CI | `:core` (نماذج حقيقية) و `:app` |
| **تشغيل فعلي على هاتف** | ⚠️ لم يُختبر هنا | لا يوجد جهاز/محاكي في بيئة التطوير |

**لم يُختبر على جهاز حقيقي في هذه البيئة**: لا يوجد محاكي Android ولا هاتف في بيئة العمل،
لذلك مسار الكاميرا والواجهة لم تُشغَّل فعليًا. ما تم التحقق منه هو: تصريف الكود بالكامل،
نجاح اختبارات المحرك على النماذج الحقيقية، وبناء APK ناجح في CI.

## 2. المحرك (النماذج والتراخيص)

| المكوّن | النموذج | الحجم | الترخيص | المصدر | SHA-256 |
|---|---|---|---|---|---|
| كاشف الوجوه | `face_detection_yunet_2023mar.onnx` | 227 KB | **MIT** | [OpenCV Zoo](https://github.com/opencv/opencv_zoo) / ShiqiYu/libfacedetection.train | `8f2383e4…52fa4` |
| تمثيل الوجه | `face_recognition_sface_2021dec_int8.onnx` | 9.4 MB | **Apache-2.0** | OpenCV Zoo (ورقة SFace، arXiv:2205.12010) | `2b0e941e…48d78a` |

التراخيص الكاملة داخل `app/src/main/assets/licenses/`. كلا النموذجين مسموح للاستخدام الأكاديمي،
ويُشغَّلان عبر **ONNX Runtime for Android 1.19.2** (رخصة MIT) داخل التطبيق.

### سلسلة المعالجة الفعلية

```
صورة (Bitmap) → RgbImage
   ├─ PHASE 01 VALIDATION   فحص الأبعاد والتجانس، رفض الملفات غير الصالحة
   ├─ PHASE 02 DETECTION    letterbox 640×640 (بدون تكبير) → YuNet → فك رموز + NMS
   │                        + تمرير ثانٍ مكبَّر للوجوه الصغيرة (<220px)
   ├─ PHASE 03 QUALITY      محاذاة 112×112 ثم قياس: حدّة/سطوع/تباين/انحراف/ميل/حجم
   ├─ PHASE 04 EXTRACTION   Umeyama 5 نقاط → warp 112×112 → SFace → L2 normalize (128D)
   ├─ PHASE 05 SEARCH       بحث شامل (dot product) على كل سجل قابل للمقارنة
   ├─ PHASE 06 RANKING      ترتيب تنازلي + كسر التعادل بمعرّف السجل
   └─ PHASE 07 REPORT       تقرير كامل قابل للتخزين (JSON) مع كل الأزمنة
```

تفاصيل الخوارزميات والقرارات في [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## 3. الدقة المقاسة (وليست المُدَّعاة)

المعايرة على **LFW** (13,233 صورة، 5,749 هوية)، أزواج متطابقة/مختلفة، تقسيم تطوير/اختبار،
والعتبة تُختار على التطوير وتُقاس مرة واحدة على الاختبار:

| المقياس | القيمة (مجموعة الاختبار) |
|---|---|
| AUC | **0.9982** |
| EER | **1.84 %** (عند 0.2699) |
| العتبة المشحونة | **0.3265** (تشابه جيب التمام) |
| FAR عندها | 0.52 % |
| FRR عندها | 3.44 % |
| زمن الاكتشاف / التمثيل | 21.9 ms / 74.2 ms (سطح مكتب x86_64 — **ليس هاتفًا**) |

مقارنة بعتبة OpenCV Zoo الموثقة (0.363): FAR 0.23 %، FRR 5.44 %.
جدول نقاط التشغيل الكامل، وكل القيود، في [`docs/EVALUATION.md`](docs/EVALUATION.md).

## 4. البناء والتشغيل

### عبر GitHub Actions (موصى به)
```bash
git push            # يبني ويختبر ويُنتج APK
# ثم من صفحة Actions ← أحدث تشغيل ← Artifact: aurora-vision-apks
```
أو من سطر الأوامر بعد نجاح التشغيل:
```bash
gh run download --name aurora-vision-apks
adb install -r app-debug.apk
```

### محليًا
```bash
# يتطلب JDK 17 و Android SDK (compileSdk 35)
export ANDROID_HOME=/path/to/android-sdk
./gradlew :core:test             # اختبارات المحرك على النماذج الحقيقية
./gradlew :app:assembleDebug     # إنتاج APK
```

### الاختبارات
```bash
./gradlew verifyAll
```
* `:core` — 40+ اختبارًا: تكافؤ رقمي مع مرجع Python، Umeyama، إعادة التمركز، المقاييس،
  البحث والترتيب، وقرارات الجودة. **تعمل على النماذج الحقيقية** لأن `:core` وحدة JVM خالصة.
* `:app` — تشفير التمثيلات، تنسيق الجداول، منطق القرار.

### إعادة إنتاج أرقام الدقة
```bash
cd tools/reference
python3 -m venv .venv && . .venv/bin/activate
pip install onnxruntime numpy pillow opencv-python-headless
./.venv/bin/python calibrate.py --lfw /path/to/lfw/faces --refine 1 --out out
./.venv/bin/python eval_quality.py --lfw /path/to/lfw/faces --out out
./.venv/bin/python build_reports.py --refine-json out/calibration_refine1.json \
    --op-json out/op_points.json --quality-json out/quality_eval.json
```

## 5. استخدام التطبيق

1. **إدارة قاعدة الصور** → «إضافة صور إلى القاعدة» → اختر صورًا مصرحًا باستخدامها.
   كل صورة تُحلَّل فعليًا (اكتشاف + جودة + تمثيل)، والمكرر يُستبعد بـ SHA-256.
2. من الشاشة الرئيسية → «بدء تحليل صورة» → اختر صورة استعلام.
3. شاهد المراحل السبع وهي تُنفَّذ فعليًا (لكل مرحلة زمنها المقاس).
4. النتيجة: أفضل 5 نتائج (قابل للتغيير) مع الدرجة والمصدر والتاريخ، أو **«لم يُعثر على تطابق موثوق»**.
5. يمكن حذف الصور المسجلة، وسجلات البحث، وكل البيانات من شاشة المعلومات.

## 6. الخصوصية

* كل المعالجة محلية؛ لا يوجد كود شبكة في مسار التحليل (صلاحية الإنترنت غير مستخدمة فيه).
* التمثيلات الرقمية محفوظة **مشفّرة AES-256-GCM** بمفتاح داخل Android Keystore.
* النسخ الاحتياطي السحابي والنقل بين الأجهزة **معطّلان** لهذا التطبيق.
* لا تُكتب بيانات الوجه في أي سجل أخطاء.
* الصور تُحفظ فقط للملفات التي أضافها المستخدم ولصورة الاستعلام، وتُحذف مع سجلها.

التفصيل في [`docs/PRIVACY.md`](docs/PRIVACY.md).

## 7. حدود معروفة (بصراحة)

1. **لم يُشغَّل على جهاز**: الواجهة والكاميرا لم تُجرَّبا على هاتف في هذه البيئة.
2. **LFW سهل نسبيًا**: النتائج على صور هاتف واقعية (إضاءة سيئة، حركة، زوايا) ستكون أقل.
3. **بوابة الحدّة** ليست مصنّف تمويه موثوق للوجوه الصغيرة جدًا (تكبير المحاذاة يعيد ترددات عالية).
   لذلك تُعرض حالة الجودة دائمًا، ولا تُقدَّم درجة تشابه كموثوقة عند جودة ضعيفة.
4. **العتبة** معايرة على LFW؛ الاستخدام في نطاق صور مختلف يستلزم إعادة معايرة.
5. **البحث شامل (exhaustive)**: مناسب حتى ~50k سجل؛ ما بعده يلزم فهرس تقريبي.
6. الأسماء العربية في الشيفرة/التعليقات مختلطة بالإنجليزية عمدًا (مصطلحات تقنية).

```
app/                 تطبيق Android (Compose + Room + CameraX + ONNX Runtime)
  src/main/assets/models/         النماذج ONNX (MIT / Apache-2.0)
```
